Antes de comenzar

Este material está dirigido a personas que empiezan desde cero. Avanza capítulo por capítulo, realiza las prácticas y adapta los ejemplos a tu proyecto. Los avances se guardan únicamente en este navegador; no se sincronizan con tu cuenta de Pixel Forge.

Cómo usar este manual: lee el concepto, realiza los pasos, prueba el resultado y marca el capítulo cuando termines. Los enlaces externos abren documentación de sus responsables.
CAPÍTULO 01

Introducción a la programación

Programar es escribir instrucciones precisas para que una computadora realice una tarea. Un programa recibe datos, procesa esos datos mediante reglas y produce un resultado. No necesitas memorizar un lenguaje completo: primero aprende a dividir un problema en pasos pequeños.

Algoritmo

Secuencia finita y ordenada de pasos para resolver un problema. Ejemplo: preparar una bebida, desde llenar el vaso hasta servir.

Lenguaje

Conjunto de reglas y palabras que permite expresar instrucciones: Python, JavaScript, C#, GDScript o Dart.

Programa

Implementación de un algoritmo en un lenguaje que el entorno puede ejecutar.

Los bloques fundamentales

  • Variables: nombres asociados a valores, por ejemplo puntos = 0.
  • Tipos: números, texto, valores booleanos y colecciones.
  • Condiciones: permiten elegir una ruta: si ocurre algo, entonces...
  • Ciclos: repiten instrucciones mientras se cumpla una condición o por cada elemento.
  • Funciones: agrupan instrucciones con un nombre y pueden recibir datos y devolver resultados.
  • Errores: sintaxis (reglas mal escritas), ejecución (falla al correr) y lógica (el programa corre, pero responde mal).

Ejemplo cotidiano convertido en algoritmo

  1. Leer el total de una compra.
  2. Si el total supera 500, calcular un descuento del 10 %.
  3. Mostrar el importe final.
total = 650
if total > 500:
    total = total * 0.90
print("Total a pagar:", total)

Prueba mental: con un total de 400 no se aplica descuento; con 650 el resultado es 585. Practica describiendo primero la solución con palabras y después tradúcela a código.

CAPÍTULO 02

Preparación del entorno de trabajo

Un entorno de trabajo reúne el equipo, el sistema operativo, el editor, los SDK o motores y las herramientas para probar el proyecto. Una computadora reciente de uso general suele bastar para comenzar con páginas web y ejercicios; el desarrollo 3D y los emuladores móviles pueden exigir más memoria y una GPU compatible.

Ruta de instalación sugerida en Windows

  1. Actualiza Windows y comprueba que tengas espacio disponible.
  2. Instala Visual Studio Code.
  3. En VS Code instala extensiones solo desde el Marketplace oficial; para HTML/CSS/JS puedes empezar sin extensiones adicionales.
  4. Descarga Godot 4 para el primer videojuego. La versión estándar es suficiente para GDScript.
  5. Para Flutter, sigue la guía oficial de instalación de Flutter, instala el SDK y Android Studio si vas a usar el emulador Android.
  6. Abre una terminal y ejecuta flutter doctor; corrige los elementos que el diagnóstico marque como pendientes.
  7. Crea una carpeta por proyecto y conserva nombres claros: assets, scenes, scripts o lib, según la herramienta.
Consejo: instala una herramienta a la vez y abre un proyecto de prueba antes de agregar otras. Así podrás identificar qué instalación causó un problema.

Desarrollo de videojuegos

Un videojuego combina reglas, entrada del jugador, gráficos, sonido, físicas y estados. El motor organiza estos elementos y ofrece herramientas para construir escenas, importar recursos, probar y exportar.

Godot + GDScript

Motor gratuito y de código abierto; GDScript tiene sintaxis sencilla y está integrado con el editor. Buena ruta 2D inicial.

Sitio oficial

Unity + C#

Motor ampliamente usado en 2D, 3D y experiencias interactivas. Requiere aprender C# y el flujo de escenas y componentes.

Sitio oficial

Unreal Engine

Motor 3D avanzado con Blueprints visuales y C++. Puede requerir hardware más potente.

Sitio oficial

Scratch

Entorno visual por bloques para aprender secuencias, eventos, ciclos y condiciones sin comenzar escribiendo sintaxis.

Tutorial: juego 2D de recolección en Godot 4

Resultado: controlarás un personaje visto desde arriba, recogerás monedas, sumarás puntos y terminarás al recogerlas todas. El tutorial usa formas simples para que no dependas de imágenes externas. Requiere Godot 4.x; consulta la documentación estable si tu versión cambia.

  1. Abre Godot, selecciona New Project, escribe Recolector2D y crea el proyecto con renderizador recomendado para tu equipo.
  2. En Project > Project Settings > Display > Window, configura una ventana de 960 × 540. En Input Map agrega las acciones mover_izquierda, mover_derecha, mover_arriba, mover_abajo y asigna A/D/W/S o flechas.
  3. Crea una escena Player.tscn con raíz CharacterBody2D llamada Player. Añade CollisionShape2D con forma CircleShape2D y un Polygon2D o Sprite2D como apariencia. Guarda en scenes/.
  4. Adjunta el script scripts/player.gd a Player:
extends CharacterBody2D

@export var speed: float = 260.0

func _physics_process(_delta: float) -> void:
    var direction := Input.get_vector(
        "mover_izquierda", "mover_derecha",
        "mover_arriba", "mover_abajo"
    )
    velocity = direction * speed
    move_and_slide()
    var bounds := get_viewport_rect().size
    position = position.clamp(Vector2(16, 16), bounds - Vector2(16, 16))

extends Area2D

  1. Crea Main.tscn con raíz Node2D llamada Main. Añade una instancia de Player como hijo directo y crea un nodo Node2D llamado Coins; coloca dentro varias instancias de Coin. Distribúyelas dentro del área visible.
  2. Añade un CanvasLayer llamado HUD y, dentro, un VBoxContainer con cuatro nodos: ScoreLabel (Label), StateLabel (Label), StartButton (Button, texto “Iniciar”) y RestartButton (Button, texto “Volver a jugar”). El árbol debe quedar así: Main/Player, Main/Coins/Coin... y Main/HUD/VBoxContainer/(ScoreLabel, StateLabel, StartButton, RestartButton).
  3. Adjunta a Main el script siguiente. Los botones se conectan desde código para que no tengas que crear conexiones manuales:
extends Node2D

@onready var score_label: Label = $HUD/VBoxContainer/ScoreLabel
@onready var state_label: Label = $HUD/VBoxContainer/StateLabel
@onready var start_button: Button = $HUD/VBoxContainer/StartButton
@onready var restart_button: Button = $HUD/VBoxContainer/RestartButton
@onready var player: CharacterBody2D = $Player
@onready var coins_root: Node2D = $Coins

var score: int = 0
var total_coins: int = 0
var started: bool = false

func _ready() -> void:
    var coins := coins_root.get_children()
    total_coins = coins.size()
    player.set_physics_process(false)
    for coin in coins:
        coin.collected.connect(_on_coin_collected)
        coin.hide()
    start_button.pressed.connect(_start_game)
    restart_button.pressed.connect(_restart_game)
    restart_button.hide()
    state_label.text = "Presiona Iniciar para comenzar"
    _update_score()

func _start_game() -> void:
    started = true
    player.position = get_viewport_rect().size / 2.0
    player.set_physics_process(true)
    for coin in coins_root.get_children():
        coin.show()
    start_button.hide()
    state_label.text = "¡Recoge todas las monedas!"
    if total_coins == 0:
        _finish_game()

func _on_coin_collected() -> void:
    if not started:
        return
    score += 1
    _update_score()
    if score >= total_coins:
        _finish_game()

func _finish_game() -> void:
    started = false
    player.set_physics_process(false)
    state_label.text = "¡Nivel completado!"
    restart_button.show()

func _restart_game() -> void:
    get_tree().reload_current_scene()

func _update_score() -> void:
    score_label.text = "Monedas: %d / %d" % [score, total_coins]
Importante para que funcione: las monedas deben ser hijas del nodo Coins y llamarse/instanciarse desde la escena Coin. La ruta de los nodos HUD debe coincidir exactamente con el árbol indicado. Cada Coin emite la señal collected y se elimina con queue_free().
  1. Define Main.tscn como escena principal desde Project > Project Settings > Application > Run o pulsa el botón para establecer la escena actual.
  2. Ejecuta con F6 para probar la escena o F5 para el proyecto. Comprueba movimiento, límites, colisiones y puntuación.
  3. Para una pantalla de inicio y final, crea un Control con botones Iniciar/Reintentar y un panel de resultado. Ocúltalo al empezar; al terminar, muéstralo. Conecta las señales pressed de los botones a funciones que reinicien la escena o cambien el estado del juego.

Pruebas mínimas

  • El personaje se mueve en cuatro direcciones y no se desplaza cuando no pulsas nada.
  • Una moneda desaparece una sola vez y el contador aumenta exactamente uno.
  • Al recoger todas las monedas aparece el mensaje de nivel completado.
  • La escena se ejecuta con el tamaño de ventana definido.

Este ejemplo enseña nodos, escenas, físicas, señales y HUD. Para una versión con enemigos, temporizador y reinicio completo, sigue el tutorial oficial Tu primer juego 2D.

CAPÍTULO 04

Desarrollo de aplicaciones móviles

Una aplicación móvil presenta información y permite realizar acciones con controles táctiles. Flutter usa Dart para crear interfaces desde una base de código; Android Studio ofrece emulador y herramientas Android. MIT App Inventor permite aprender con bloques visuales.

Herramientas

  • Flutter/Dart: aplicaciones multiplataforma con widgets.
  • Android Studio: SDK, emuladores y herramientas de compilación Android.
  • VS Code: editor ligero con extensiones oficiales de Flutter y Dart.
  • MIT App Inventor: prototipos educativos mediante programación por bloques.

Tutorial: lista de tareas en Flutter

  1. Instala Flutter siguiendo la guía oficial para tu sistema.
  2. Instala Android Studio y un Android SDK compatible si probarás en emulador.
  3. En terminal ejecuta flutter doctor y resuelve los avisos antes de continuar.
  4. Ejecuta flutter create lista_tareas y entra en la carpeta con cd lista_tareas.
  5. Abre lib/main.dart y reemplaza su contenido por este ejemplo.
import 'package:flutter/material.dart';

void main() => runApp(const TodoApp());

class Task {
  Task(this.title);
  final String title;
  bool done = false;
}

class TodoApp extends StatelessWidget {
  const TodoApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      title: 'Mi lista de tareas',
      theme: ThemeData(colorSchemeSeed: Colors.deepPurple,
          useMaterial3: true),
      home: const TodoPage(),
    );
  }
}

class TodoPage extends StatefulWidget {
  const TodoPage({super.key});

  @override
  State<TodoPage> createState() => _TodoPageState();
}

class _TodoPageState extends State<TodoPage> {
  final List<Task> tasks = [];
  final TextEditingController controller = TextEditingController();

  void addTask() {
    final title = controller.text.trim();
    if (title.isEmpty) return;
    setState(() {
      tasks.add(Task(title));
      controller.clear();
    });
  }

  void toggleTask(int index, bool? value) {
    setState(() => tasks[index].done = value ?? false);
  }

  void deleteTask(int index) {
    setState(() => tasks.removeAt(index));
  }

  @override
  void dispose() {
    controller.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Mis tareas')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(children: [
          Row(children: [
            Expanded(child: TextField(
              controller: controller,
              decoration: const InputDecoration(
                labelText: 'Nueva tarea', border: OutlineInputBorder()),
              onSubmitted: (_) => addTask(),
            )),
            const SizedBox(width: 8),
            FilledButton(onPressed: addTask, child: const Icon(Icons.add)),
          ]),
          const SizedBox(height: 16),
          Expanded(child: tasks.isEmpty
            ? const Center(child: Text('Aún no tienes tareas.'))
            : ListView.builder(
                itemCount: tasks.length,
                itemBuilder: (context, index) {
                  final task = tasks[index];
                  return Card(child: ListTile(
                    leading: Checkbox(value: task.done,
                      onChanged: (value) => toggleTask(index, value)),
                    title: Text(task.title,
                      style: TextStyle(decoration: task.done
                        ? TextDecoration.lineThrough : null)),
                    trailing: IconButton(
                      tooltip: 'Eliminar tarea',
                      icon: const Icon(Icons.delete_outline),
                      onPressed: () => deleteTask(index),
                    ),
                  ));
                },
              )),
        ]),
      ),
    );
  }
}
  1. Conecta un emulador o dispositivo con depuración USB habilitada y autorizada.
  2. En la carpeta del proyecto ejecuta flutter run. Para compilar una versión Android de distribución, revisa la guía oficial de despliegue y firma; no compartas claves de firma.
  3. Prueba agregar una tarea, marcarla, desmarcarla, eliminarla y enviar el formulario con el campo vacío.
Alcance: este ejemplo mantiene tareas en memoria. Al cerrar la aplicación se pierden; para conservarlas agrega persistencia local o una base de datos después de estudiar almacenamiento seguro.

Errores frecuentes y soluciones

ProblemaCausa probableCómo identificarloQué hacer
Error de sintaxisParéntesis, comillas, sangría o nombre mal escrito.El editor marca una línea o el intérprete no inicia.Lee el primer error, revisa la línea y las anteriores; corrige una cosa a la vez.
Programa no ejecutaHerramienta no instalada o terminal en carpeta incorrecta.Comando no reconocido o archivo no encontrado.Verifica instalación, PATH, carpeta actual y nombre exacto del archivo.
Archivo no apareceGuardado en una carpeta distinta o extensión oculta.La ruta del proyecto no coincide.Usa el explorador del editor y evita duplicar extensiones como .txt.
Escena de Godot vacíaEscena principal incorrecta o nodo no agregado.El proyecto inicia sin el contenido esperado.Revisa la escena principal, el árbol de nodos y los errores del panel Output.
Flutter no compilaSDK, dependencia o dispositivo sin configurar.flutter doctor muestra alertas o build falla.Ejecuta diagnóstico, lee el primer error y sigue la guía oficial del componente que falta.
Web sin estilosRuta CSS incorrecta o archivo no guardado.Se ve HTML sin diseño.Comprueba el nombre/ruta en link y recarga sin caché.
Conexión/API fallaURL, clave, permisos, CORS o red.Error de red o respuesta HTTP no exitosa.Verifica URL, credenciales públicas permitidas, permisos y consola; nunca publiques secretos.

Método de depuración en cinco pasos

  1. Reproduce el problema.
  2. Lee el mensaje completo, empezando por el primer error.
  3. Identifica archivo y línea.
  4. Cambia una sola cosa y vuelve a probar.
  5. Registra la solución para evitar repetirla.

CAPÍTULO 08

Ejercicios prácticos

Nivel básico

  1. Declara variables para tu alias, edad y juego favorito; muestra una frase con esos datos.
  2. Calcula el promedio de tres calificaciones y muestra si es aprobatorio según un umbral que tú declares.
  3. Crea una función que convierta minutos en segundos.
Soluciones orientativas del nivel básico
alias = "Player01"
edad = 18
juego = "Aventura"
print(alias, edad, juego)

calificaciones = [8, 9, 7]
promedio = sum(calificaciones) / len(calificaciones)
print(promedio, "Aprobado" if promedio >= 7 else "No aprobado")

def a_segundos(minutos):
    return minutos * 60
print(a_segundos(5))

Nivel intermedio

  1. Modifica la lista Flutter para editar una tarea antes de borrarla.
  2. Añade al portafolio una tarjeta nueva y un filtro por categoría.
  3. En Godot, limita el movimiento del personaje dentro del área visible.
Pistas del nivel intermedio
  • Para editar Flutter, abre un diálogo con un campo de texto y actualiza el elemento dentro de setState.
  • Para filtrar tarjetas, añade un atributo data-categoria y compara el valor seleccionado.
  • Para limitar al personaje, usa clampf(position.x, min_x, max_x) y su equivalente en Y.

Nivel de aplicación

  1. Construye un mini juego con tres niveles y puntuación.
  2. Amplía la lista Flutter para guardar localmente las tareas.
  3. Publica tu portafolio en un hosting estático y valida el diseño móvil.

Entrega: captura o enlace del resultado, descripción del objetivo, herramientas usadas, dificultad encontrada y cómo la resolviste.

CAPÍTULO 10

Proyecto final

Elige una ruta y construye un producto pequeño pero terminado. La meta es demostrar el proceso completo, no competir por la cantidad de funciones.

Opción A · Videojuego 2D

Objetivo: juego con personaje, objetivo, puntuación y pantalla final. Herramienta: Godot 4. Entrega: proyecto, controles, instrucciones y video corto de prueba.

Opción B · Aplicación móvil

Objetivo: lista de tareas con alta, completado y eliminación. Herramienta: Flutter. Entrega: código, capturas en emulador y explicación de estado y almacenamiento.

Opción C · Página web

Objetivo: portafolio responsivo con navegación y una interacción. Herramientas: HTML, CSS y JavaScript. Entrega: archivos y enlace publicado si tienes hosting.

Procedimiento

  1. Escribe el problema y a quién ayuda tu proyecto.
  2. Define tres funciones indispensables y separa las mejoras opcionales.
  3. Dibuja un boceto de pantallas o escenas.
  4. Prepara herramientas, carpetas y recursos con licencia adecuada.
  5. Construye una función a la vez y realiza pruebas.
  6. Documenta instalación, ejecución, controles y limitaciones.
  7. Presenta el proyecto y reflexiona sobre lo que mejorarías.

Rúbrica sugerida

CriterioPonderaciónQué se observa
Funcionamiento30 %Las funciones principales se ejecutan.
Organización20 %Archivos y nombres claros.
Diseño y accesibilidad15 %Lectura, navegación y adaptación.
Pruebas20 %Casos probados y errores corregidos.
Documentación15 %Instrucciones y reflexión comprensibles.

CAPÍTULO 11

Glosario de programación

Algoritmo
Pasos ordenados para resolver una tarea.
API
Interfaz que permite que dos programas se comuniquen.
Array / lista
Colección ordenada de elementos.
Bug
Error o comportamiento no deseado.
Compilador
Herramienta que transforma código a otra representación ejecutable.
Condición
Expresión evaluada como verdadera o falsa.
Depuración
Proceso de localizar y corregir errores.
Evento
Acción que puede activar una respuesta del programa.
Función
Bloque reutilizable de instrucciones.
IDE
Entorno integrado para editar, ejecutar y depurar.
Interfaz
Medio con el que una persona interactúa con un sistema.
Loop / ciclo
Repetición controlada de instrucciones.
Objeto
Instancia con datos y comportamiento en programación orientada a objetos.
Repositorio
Espacio donde se guarda un proyecto y su historial.
SDK
Conjunto de herramientas para desarrollar para una plataforma.
Variable
Nombre que referencia un valor.

CAPÍTULO 12

Conclusión

Aprender programación es una práctica gradual. Cada proyecto enseña a plantear problemas, dividirlos, escribir instrucciones, probar resultados y corregir fallos. No necesitas dominar todas las herramientas a la vez.

Empieza con una meta alcanzable, conserva versiones de tu trabajo y pide retroalimentación. Después amplía tu proyecto con funciones nuevas. PIXEL FORGE — Imagina, aprende, experimenta y crea tu propio mundo digital.
